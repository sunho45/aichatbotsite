이 프로젝트에서 로컬 수정 사항과 비밀 환경 파일을 잃지 않기 위한 실전 Git 사용법입니다.

Git 가이드 JavaScript 문법 가이드

명령어를 실행하는 위치

Git 명령어는 프로젝트 루트 폴더에서 실행하는 것이 가장 안전합니다.

cd C:\Users\skyee\Documents\my_aiwebsite

server 폴더는 같은 저장소 안에 있습니다. 보통 server 안에서 따로 Git을 실행할 필요는 없습니다.

기본 작업 흐름

  1. 무엇이 바뀌었는지 확인합니다.
  2. 실제 코드 차이를 검토합니다.
  3. 저장하고 싶은 파일만 stage 합니다.
  4. 명확한 메시지로 commit 합니다.
  5. 원격 저장소에 올릴 준비가 되었을 때 push 합니다.
git status
git diff
git add server/server.js server/package.json server/package-lock.json
git commit -m "Refactor server to use express"
git push

자주 쓰는 명령어

명령어 설명
git status 변경된 파일, stage 된 파일, 새 파일, 삭제된 파일을 보여줍니다.
git diff 아직 stage 하지 않은 수정 내용을 줄 단위로 보여줍니다.
git diff --staged 다음 commit에 들어갈 내용을 보여줍니다.
git add file 특정 파일 하나를 다음 commit 대상으로 올립니다.
git add -p 파일의 일부 변경만 골라서 stage 합니다.
git commit -m "message" stage 된 변경 사항으로 commit을 만듭니다.
git log --oneline --decorate -10 최근 commit 10개를 간단히 확인합니다.
git branch 현재 branch와 로컬 branch 목록을 확인합니다.
git switch branch-name 이미 존재하는 branch로 이동합니다.
git switch -c branch-name 새 branch를 만들고 바로 이동합니다.

안전한 Commit 절차

서버 리팩터링 파일만 commit하고 싶을 때는 아래처럼 파일을 명확히 지정합니다.

git status
git diff -- server/server.js server/package.json server/package-lock.json
git add server/server.js server/package.json server/package-lock.json
git diff --staged
git commit -m "Refactor API server to Express"

관련 없는 파일이나 생성 파일이 섞여 있을 수 있으므로 git add .는 조심해서 사용하세요.

무시되는 파일과 .env

API key 같은 비밀 값은 commit하면 안 됩니다. 이 프로젝트는 환경 파일을 무시하도록 설정되어 있습니다.

.env
.env.local
.env.*

server/.env가 내 컴퓨터에 있어도 일반 commit 대상에는 나타나지 않을 수 있습니다.

git status --ignored
git check-ignore -v server/.env

실제 API key는 절대 commit하지 마세요. OPENROUTER_API_KEY와 ELEVENLABS_API_KEY는 server/.env에만 보관하세요.

Pull 하기 전 확인

다른 사람이 올린 변경 사항을 받기 전에 내 변경 사항을 먼저 확인합니다.

git status
git diff

아직 commit하기 애매한 작업은 잠시 stash 할 수 있습니다.

git stash push -m "work in progress"
git pull
git stash pop

git stash pop 후 충돌이 생기면 파일에 표시된 충돌 부분을 직접 고친 뒤 commit해야 합니다.

되돌리기 명령어

상황 명령어
파일을 stage에서 내리고 수정은 유지 git restore --staged file
tracked 파일 하나의 수정 삭제 git restore file
삭제된 tracked 파일 확인 git status
마지막 commit 상태로 파일 복구 git restore file

git reset --hard는 tracked local 변경 사항을 지웁니다. 정확히 이해한 경우에만 사용하세요.

이 프로젝트에서 추천하는 규칙

  • 소스 파일과 dependency 변경 시 lockfile을 함께 commit합니다.
  • node_modules는 보통 npm install로 생성되므로 commit하지 않는 편이 좋습니다.
  • API key는 server/.env에만 둡니다.
  • commit 전에는 항상 git diff를 확인합니다.
  • 큰 변경이나 위험한 변경은 새 branch에서 작업합니다.
git switch -c feature/server-express-refactor
