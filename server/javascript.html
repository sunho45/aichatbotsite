JavaScript 문법 가이드

서버와 프론트엔드 코드를 읽고 수정할 때 자주 만나는 JavaScript 문법을 정리했습니다.

변수 선언

const는 다시 할당하지 않는 값, let은 다시 할당할 수 있는 값에 사용합니다. var는 오래된 방식이라 새 코드에서는 피하는 편이 좋습니다.

const port = 3000;
let count = 0;

count = count + 1;

자료형

자료형 예시
문자열 "hello", 'hello', `hello ${name}`
숫자 10, 3.14
불리언 true, false
배열 ["user", "assistant"]
객체 { name: "server", port: 3000 }
null / undefined 값이 비어 있거나 아직 정해지지 않은 상태

함수

일반 함수와 화살표 함수는 모두 자주 사용됩니다.

function add(a, b) {
  return a + b;
}

const multiply = (a, b) => {
  return a * b;
};

Express route handler처럼 이름이 있는 함수는 에러 추적과 재사용에 유리합니다.

조건문

if, else if, else로 조건에 따라 다른 코드를 실행합니다.

if (!apiKey) {
  res.status(500).json({ error: "Missing API key" });
} else {
  startServer();
}

배열 메서드

배열 데이터를 다룰 때 filter, map, slice, some을 많이 사용합니다.

const messages = incomingMessages
  .filter((message) => message.role === "user")
  .slice(-20)
  .map((message) => ({
    role: message.role,
    content: message.content.trim(),
  }));
  • filter: 조건에 맞는 항목만 남깁니다.
  • map: 각 항목을 다른 형태로 바꿉니다.
  • slice: 배열의 일부를 복사합니다.
  • some: 조건을 만족하는 항목이 하나라도 있는지 확인합니다.

객체와 구조 분해

객체는 이름이 있는 값 묶음입니다. 필요한 값만 꺼낼 때 구조 분해를 사용할 수 있습니다.

const user = {
  name: "Sky",
  role: "admin",
};

const { name, role } = user;

옵셔널 체이닝과 기본값

?.는 중간 값이 없을 때 에러 대신 undefined를 반환합니다. ||는 기본값을 지정할 때 자주 사용합니다.

const apiKey = process.env.OPENROUTER_API_KEY || process.env.XAI_API_KEY;
const reply = data.choices?.[0]?.message?.content;

||는 빈 문자열도 false로 처리합니다. 빈 문자열을 유효한 값으로 봐야 한다면 ??를 고려하세요.

비동기 코드

API 호출, 파일 읽기, 네트워크 요청은 시간이 걸릴 수 있으므로 async와 await를 사용합니다.

async function handleChat(req, res) {
  const response = await fetch("https://example.com/api", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ message: "hello" }),
  });

  const data = await response.json();
  res.json(data);
}

try / catch

실패할 수 있는 코드는 try / catch로 감싸서 서버가 갑자기 종료되지 않도록 처리합니다.

try {
  const data = await response.json();
  res.json(data);
} catch (error) {
  console.error(error);
  res.status(500).json({ error: "Server error" });
}

CommonJS 모듈

현재 서버는 type: "commonjs" 방식입니다. 그래서 require로 모듈을 불러옵니다.

const express = require("express");
const cors = require("cors");

const app = express();

Express 기본 구조

Express 서버는 middleware, route, error handler 순서로 읽으면 이해하기 쉽습니다.

app.use(cors());
app.use(express.json());

app.post("/api/chat", handleChat);

app.use((error, req, res, next) => {
  console.error(error);
  res.status(500).json({ error: "Server error" });
});

위에서 아래로 실행되므로 middleware와 route 순서가 중요합니다.
