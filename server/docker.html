Docker란?

Docker는 애플리케이션과 실행 환경을 컨테이너라는 단위로 묶어서 실행하는 도구입니다. 내 컴퓨터, 테스트 서버, 운영 서버에서 같은 방식으로 실행할 수 있게 해줍니다.

  • 이미지: 컨테이너를 만들기 위한 실행 템플릿입니다.
  • 컨테이너: 이미지를 실제로 실행한 프로세스입니다.
  • Dockerfile: 이미지를 만드는 방법을 적어두는 파일입니다.
  • 볼륨: 컨테이너가 삭제되어도 데이터를 남기기 위한 저장 공간입니다.
  • 포트 매핑: 내 컴퓨터의 포트와 컨테이너 내부 포트를 연결하는 설정입니다.

기본 명령어

명령어 설명
docker --version Docker 버전을 확인합니다.
docker pull nginx Docker Hub에서 Nginx 이미지를 내려받습니다.
docker images 내 컴퓨터에 내려받은 이미지 목록을 봅니다.
docker ps 실행 중인 컨테이너 목록을 봅니다.
docker ps -a 중지된 컨테이너까지 모두 봅니다.
docker logs 컨테이너명 컨테이너 로그를 확인합니다.
docker stop 컨테이너명 실행 중인 컨테이너를 중지합니다.

Docker Compose란?

Docker Compose는 여러 컨테이너를 하나의 YAML 파일로 함께 실행하고 관리하는 도구입니다. 웹 서버, 데이터베이스, 관리자 도구처럼 서로 연결된 서비스를 한 번에 올릴 때 사용합니다.

기본 파일명이 docker-compose.yml이면 프로젝트 루트에서 아래 명령만 실행해도 Compose가 자동으로 파일을 찾아 실행합니다.

docker compose up -d

-d는 detached 모드라는 뜻입니다. 터미널을 붙잡아두지 않고 백그라운드에서 컨테이너를 실행합니다.

이번 실습 구성

프로젝트 루트에 만든 docker-compose.yml은 세 개의 서비스를 실행합니다.

서비스 역할 접속
web Nginx로 실습용 HTML 페이지를 보여줍니다. http://localhost:8080
db PostgreSQL 데이터베이스를 실행합니다. localhost:5432
adminer 브라우저에서 DB를 확인하는 관리 도구입니다. http://localhost:8081

실행하기

docker compose up -d

상태 확인하기

docker compose ps

로그 보기

docker compose logs web
docker compose logs db
docker compose logs adminer

중지하고 삭제하기

docker compose down

DB 데이터 볼륨까지 삭제하기

docker compose down -v
주의: docker compose down -v는 PostgreSQL 데이터가 들어 있는 볼륨까지 삭제합니다. DB 데이터를 남기고 싶으면 -v를 붙이지 않습니다.

Adminer 접속 정보

http://localhost:8081로 접속한 뒤 아래 값을 입력합니다.

System PostgreSQL
Server db
Username practice_user
Password practice_password
Database practice

여기서 Server를 localhost가 아니라 db로 쓰는 이유는 Compose 내부 네트워크에서 서비스 이름이 곧 호스트 이름처럼 동작하기 때문입니다.

docker-compose.yml 핵심 구조

services:
  web:
    image: nginx:1.27-alpine
    ports:
      - "8080:80"

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: practice
      POSTGRES_USER: practice_user
      POSTGRES_PASSWORD: practice_password

volumes:
  compose-practice-db-data:
  • services: 실행할 컨테이너 목록입니다.
  • image: 사용할 Docker 이미지입니다.
  • ports: 내 컴퓨터 포트와 컨테이너 포트를 연결합니다. 예를 들어 "8080:80"은 내 컴퓨터의 8080번을 컨테이너의 80번에 연결합니다.
  • environment: 컨테이너에 전달할 환경변수입니다.
  • volumes: 데이터나 파일을 컨테이너에 연결합니다.
  • depends_on: 다른 서비스가 먼저 준비된 뒤 실행되도록 순서를 잡습니다.
  • healthcheck: 컨테이너가 실제로 사용할 준비가 되었는지 검사합니다.

DB에 직접 접속하기

PostgreSQL 컨테이너 안으로 들어가 SQL을 직접 실행할 수 있습니다.

docker compose exec db psql -U practice_user -d practice

접속 후 아래 SQL을 실행해볼 수 있습니다.

SELECT * FROM todos;
INSERT INTO todos (title) VALUES ('Compose로 DB 데이터 추가하기');
SELECT * FROM todos;

나가려면 \q를 입력합니다.

문제가 생겼을 때

상황 확인할 것
포트가 이미 사용 중이라고 나올 때 docker-compose.yml의 8080:80, 8081:8080, 5432:5432 중 왼쪽 포트 번호를 다른 번호로 바꿉니다.
Docker API 권한 오류가 날 때 Docker Desktop이 실행 중인지 확인하고, 현재 터미널이 Docker에 접근할 권한이 있는지 확인합니다.
DB가 바로 접속되지 않을 때 docker compose ps에서 db 상태가 healthy인지 확인합니다.
변경한 HTML이 안 보일 때 compose-practice/index.html을 수정한 뒤 브라우저 새로고침을 합니다. 이 파일은 볼륨으로 nginx 컨테이너에 연결되어 있습니다.
정리: 지금 실습의 핵심은 docker compose up -d 한 번으로 웹, DB, DB 관리 도구를 같이 실행하고, docker compose down으로 한 번에 정리하는 흐름입니다.
