Nginx란?

Nginx는 웹 서버입니다. HTML, CSS, JS, 이미지 같은 정적 파일을 브라우저에 보내거나, Node.js 같은 백엔드 서버 앞에서 요청을 대신 받아 전달하는 리버스 프록시 역할을 할 수 있습니다.

  • 정적 파일 서버: 빌드된 프론트엔드 파일을 빠르게 제공합니다.
  • 리버스 프록시: 외부 요청을 내부 애플리케이션 서버로 전달합니다.
  • 라우팅: URL 경로별로 서로 다른 동작을 하게 만들 수 있습니다.
  • 캐싱과 압축: 정적 파일 응답을 빠르게 만들 수 있습니다.

이번 실습의 nginx.conf

현재 Compose 실습에서 사용하는 파일은 compose-practice/nginx.conf입니다. 이 설정은 nginx 컨테이너 안의 /usr/share/nginx/html/index.html을 보여줍니다.

server {
    listen 80;
    server_name localhost;

    location / {
        root /usr/share/nginx/html;
        index index.html;
    }
}
설정 뜻
server 하나의 웹 서버 규칙 묶음입니다.
listen 80 컨테이너 내부 80번 포트에서 HTTP 요청을 받습니다.
server_name localhost 이 서버 블록이 처리할 호스트 이름입니다. 로컬 실습에서는 localhost를 씁니다.
location / /로 시작하는 모든 요청을 처리합니다.
root 파일을 찾을 기준 폴더입니다.
index index.html 폴더 요청이 들어오면 기본으로 보여줄 파일입니다.

Docker Compose와 연결되는 부분

docker-compose.yml의 web 서비스는 nginx 이미지를 실행하고, 내 컴퓨터 파일을 컨테이너 안으로 연결합니다.

web:
  image: nginx:1.27-alpine
  container_name: compose-practice-web
  ports:
    - "8080:80"
  volumes:
    - ./compose-practice/index.html:/usr/share/nginx/html/index.html:ro
    - ./compose-practice/nginx.conf:/etc/nginx/conf.d/default.conf:ro
  • "8080:80": 내 컴퓨터의 8080 포트를 nginx 컨테이너의 80 포트에 연결합니다.
  • index.html 볼륨: 로컬 HTML 파일을 nginx가 제공하는 위치에 연결합니다.
  • nginx.conf 볼륨: 로컬 nginx 설정 파일을 컨테이너 기본 설정 위치에 연결합니다.
  • :ro: read-only입니다. 컨테이너 안에서 이 파일을 수정하지 못하게 막습니다.
흐름: 브라우저가 http://localhost:8080으로 요청하면 Docker가 컨테이너의 80번 포트로 넘기고, nginx가 index.html을 응답합니다.

정적 파일 서버 예시

HTML, CSS, JS 파일을 그냥 제공하는 가장 기본적인 설정입니다.

server {
    listen 80;
    server_name example.local;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}

try_files $uri $uri/ =404는 요청한 파일이 있으면 보내고, 폴더가 있으면 폴더를 확인하고, 둘 다 없으면 404를 응답하라는 뜻입니다.

React/Vite 같은 SPA 설정

React Router처럼 브라우저 라우팅을 쓰는 앱은 /about, /dashboard 같은 주소로 새로고침했을 때도 index.html을 보내야 합니다.

server {
    listen 80;
    server_name localhost;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}

마지막이 /index.html인 점이 중요합니다. 파일이 없다고 바로 404를 내는 대신 React 앱 진입 파일로 돌려보냅니다.

Node.js 서버로 넘기는 리버스 프록시

Nginx는 직접 백엔드 역할을 하기보다, 앞단에서 요청을 받고 Node.js 서버로 전달하는 용도로 많이 씁니다.

server {
    listen 80;
    server_name localhost;

    location /api/ {
        proxy_pass http://app:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        root /usr/share/nginx/html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
}

Compose 안에서는 app, db, web 같은 서비스 이름이 내부 DNS 이름처럼 동작합니다. 그래서 proxy_pass http://app:3000처럼 쓸 수 있습니다.

WebSocket 프록시 예시

채팅, 실시간 알림처럼 WebSocket을 쓰면 업그레이드 헤더를 넘겨야 합니다.

server {
    listen 80;
    server_name localhost;

    location /ws/ {
        proxy_pass http://app:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}

Upgrade와 Connection 헤더가 빠지면 WebSocket 연결이 일반 HTTP 요청처럼 처리되어 실패할 수 있습니다.

캐시 설정 예시

JS, CSS, 이미지 같은 정적 파일은 캐시를 길게 줄 수 있습니다. HTML은 최신 화면을 보여줘야 하므로 보통 짧게 가져갑니다.

server {
    listen 80;
    server_name localhost;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico)$ {
        expires 1h;
        add_header Cache-Control "public";
    }

    location = /index.html {
        add_header Cache-Control "no-store";
    }
}

설정 확인과 재시작

nginx 설정을 바꾼 뒤에는 문법 검사 후 다시 로드하는 흐름이 기본입니다.

nginx -t
nginx -s reload

Docker Compose로 실행 중인 nginx 컨테이너에서는 이렇게 확인할 수 있습니다.

docker compose exec web nginx -t
docker compose restart web

현재 실습처럼 설정 파일을 볼륨으로 연결했다면, compose-practice/nginx.conf를 수정한 뒤 docker compose restart web을 실행하면 변경 사항이 반영됩니다.

자주 나는 실수

증상 원인과 해결
localhost:8080 접속이 안 됨 docker compose ps로 web 컨테이너가 실행 중인지 확인합니다. 포트 충돌이면 8080:80의 왼쪽 값을 바꿉니다.
설정 변경이 반영되지 않음 docker compose restart web으로 nginx 컨테이너를 재시작합니다.
React 페이지 새로고침 시 404 try_files $uri $uri/ /index.html; 설정이 필요합니다.
API 요청이 nginx에서 막힘 location /api/와 proxy_pass 경로를 확인합니다.
주의: nginx 설정은 세미콜론 하나가 빠져도 실행되지 않습니다. 설정을 바꾼 뒤에는 항상 nginx -t로 문법을 확인하는 습관이 좋습니다.
