Essential Module Grammar

Server Grammar

A practical reading guide for the syntax patterns used across this Express server: imports, exports, middleware, routes, services, async handlers, static files, and WebSockets.

How to Read a Module

1. Imports

The top of each file declares what it needs with require(...).

2. Local Logic

The middle usually contains constants, helper functions, route handlers, or service functions.

3. Exports

The bottom exposes reusable values with module.exports.

Core Grammar Patterns

CommonJS Import

const express = require("express");
const { PORT, clientDist } = require("./config/runtime");

This means the file is borrowing code from another package or local file. Curly braces pick named exports from an object.

CommonJS Export

module.exports = {
  createApiRouter,
  handleProtocolMetadata,
};

This makes functions available to other files. Another module can import them with destructuring.

Express App Setup

const app = express();
const server = http.createServer(app);

app.use(express.json({ limit: MAX_UPLOAD_SIZE }));

app handles HTTP logic. server is the lower-level HTTP server that also supports WebSocket upgrades.

Middleware

app.use(cors());
app.use(attachTransportHeaders);

Middleware runs before route handlers. It can read the request, change the response, reject the request, or pass control to the next handler.

Route Handler

app.get("/blueprint.html", (req, res) => {
  res.setHeader("Cache-Control", "no-store");
  res.sendFile(blueprintPagePath);
});

A route matches one HTTP method and path. The handler receives req for request data and res for the response.

Router Module

const router = express.Router();

router.post("/chat", handleAsync(handleChat));

app.use("/api", createApiRouter());

A router groups related routes. Mounting it at /api means /chat becomes /api/chat.

Module Grammar by Folder

Folder Grammar to Understand Why It Matters
config process.env, constants, path building, exports Turns environment values into stable settings used everywhere else.
middleware Functions shaped like (req, res, next) Middleware prepares requests and centralizes repeated response behavior.
routes HTTP verbs, routers, path strings, handler callbacks Routes decide which service should handle each incoming request.
services Async functions, validation, external API calls, returned objects Services contain the main feature behavior and keep routes thin.
utils Small pure helpers, input normalization, shared calculations Utilities remove repeated logic from routes and services.
websocket Upgrade events, buffers, frames, connection lifecycle events WebSocket code handles persistent connections instead of single HTTP responses.

Essential Express Vocabulary

req

The incoming request. Read body, params, query strings, headers, and URL data from it.

res

The outgoing response. Use it to set status codes, headers, JSON, files, or streams.

next

A callback that moves control to the next middleware or error handler.

params

Dynamic path values, such as the code in /state/:code.

query

Values after a question mark, such as ?code=404.

body

Posted JSON or form data, available after body-parsing middleware runs.

Error and Async Grammar

Async Route Wrapper

function handleAsync(fn) {
  return (req, res, next) => {
    Promise.resolve(fn(req, res, next)).catch(next);
  };
}

Async route errors do not need repeated try/catch blocks. The wrapper forwards failures to Express error middleware.

Error Middleware

function handleError(error, req, res, next) {
  console.error(error);
  res.status(500).json({ error: "Server error" });
}

Error middleware has four arguments. Express recognizes that shape and uses it when a route calls next(error).

Reading Checklist

  1. Find imports. Ask what this module depends on.
  2. Find exports. Ask what this module gives to the rest of the server.
  3. Find request shapes. Look for path params, query strings, body fields, and headers.
  4. Find response shapes. Look for status codes, JSON objects, sent files, streams, or socket frames.
  5. Trace errors. Check whether failures throw, return JSON directly, or pass through error middleware.
